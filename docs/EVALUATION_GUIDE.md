## Основные понятия

### Что делает команда evaluate?

Команда `pyparaglide evaluate` тестирует обученную модель на отложенных данных (test set) и показывает, насколько хорошо модель предсказывает лётные дни.

```bash
pyparaglide evaluate --year 2023 --model cells --threshold 0.1
```

### Матрица ошибок (Confusion Matrix)

| | Предсказано "НЕ лётно" | Предсказано "лётно" |
|---|---|---|
| **На самом деле НЕ лётно** | True Negative (TN) | False Positive (FP) |
| **На самом деле лётно** | False Negative (FN) | True Positive (TP) |

### Термины простыми словами:

- **TP (True Positive)** - Модель сказала "летай", и действительно можно было летать ✅
- **TN (True Negative)** - Модель сказала "не летай", и действительно нельзя было летать ✅
- **FP (False Positive)** - Модель сказала "летай", но нельзя было летать ❌ (приехали зря)
- **FN (False Negative)** - Модель сказала "не летай", но можно было летать ❌ (пропустили хороший день)

## Метрики качества

### ROC AUC Score

**Что это:** Число от 0 до 1, показывающее насколько хорошо модель различает лётные и нелётные дни.

| Значение | Качество |
|----------|----------|
| 0.9 - 1.0 | Отлично |
| 0.8 - 0.9 | Хорошо |
| 0.7 - 0.8 | Удовлетворительно |
| 0.5 - 0.7 | Плохо |
| 0.5 | Случайный угад |

**Пример:**
```
ROC AUC = 0.93 → модель с 93% вероятностью отличит лётный день от нелётного
```

### Accuracy (Точность)

**Что это:** Доля правильных ответов среди всех предсказаний.

**Ограничение:** Accuracy может быть обманчивой! Если лётных дней всего 5%, а модель всегда говорит "не летай", accuracy будет 95%, но модель бесполезна.

### Precision (Точность)

**Формула:** `TP / (TP + FP)`

**Что это:** Если модель сказала "летай", какая вероятность что она права?

```
Precision = 29% означает:
"Из 100 дней, когда модель сказала 'летай', 29 действительно были лётными"
```

### Recall (Полнота)

**Формула:** `TP / (TP + FN)`

**Что это:** Сколько лётных дней мы смогли поймать?

```
Recall = 99% означает:
"Модель поймала 99% всех лётных дней, пропустив только 1%"
```

### F1 Score

**Формула:** `2 × (Precision × Recall) / (Precision + Recall)`

**Что это:** Среднее гармоническое Precision и Recall. Учитывает ОБЕ метрики.

**Почему F1 важнее Accuracy:**
- F1 учитывает баланс между классами
- F1 штрафует модель, если она хорошо работает только на одном классе
- F1 = 1 идеально, F1 = 0 ужасно

## Порог классификации (Threshold)

### Что такое threshold?

Модель выдаёт вероятность от 0 до 1. Threshold - это граница решения:

```
Вероятность >= threshold → предсказываем "лётно"
Вероятность < threshold  → предсказываем "не лётно"
```

### Как threshold влияет на результаты

| Threshold | Поведение модели | FP ↑ | FN ↑ | Для кого подходит |
|-----------|------------------|------|------|------------------|
| **Низкий (0.05-0.1)** | Агрессивная - чаще говорит "летай" | Много | Мало | Тем, кто не хочет пропустить хороший день |
| **Средний (0.3-0.5)** | Сбалансированная | Средне | Средне | Универсальный вариант |
| **Высокий (0.6-0.7)** | Консервативная - редко говорит "летай" | Мало | Много | Тем, кто боится приехать зря |

### Trade-off (дилемма)

```
Низкий threshold:
+ Поймаем почти все лётные дни (высокий Recall)
- Много ложных тревог (низкий Precision)

Высокий threshold:
+ Меньше поездок зря (высокий Precision)
- Много пропущенных хороших дней (низкий Recall)
```

### Как подобрать оптимальный threshold?

#### Метод 1: Максимизировать F1

```bash
# Протестируйте разные thresholds:
pyparaglide evaluate --year 2023 --model cells --threshold 0.05
pyparaglide evaluate --year 2023 --model cells --threshold 0.1
pyparaglide evaluate --year 2023 --model cells --threshold 0.15
# ...
```

Выбирайте threshold с максимальным F1 Score.

#### Метод 2: Бизнес-логика

Задайте себе вопрос: **Что хуже?**

- **A)** Приехать на точку и не полетать (False Positive)
- **B)** Остаться дома, хотя погода была отличной (False Negative)

**Если A хуже** → используйте **высокий threshold** (0.5-0.7)
**Если B хуже** → используйте **низкий threshold** (0.05-0.15)

Для параплана обычно **B хуже**, поэтому рекомендуем низкий threshold.

#### Метод 3: Цена ошибки

```
threshold=0.1:
FP/TP = 988/356 = 2.77
"На 1 успешный день → 2.8 поездок зря"

threshold=0.2:
FP/TP = 292/118 = 2.47
"На 1 успешный день → 2.5 поездок зря"
```

Если разница в FP/TP небольшая, выбирайте вариант с более высоким Recall.

## Выходы модели (Outputs)

### CELLS модель имеет 4 выхода:

| Output | Описание | Для чего используется |
|--------|----------|---------------------|
| **flown** | Общая летальность | Принятие решения "ехать/не ехать" |
| **crossed** | XC cross-country потенциал | Оценка перспективы дальнего перелёта |
| **wind_flown** | Индикатор по ветру | Проверка ветровых условий |
| **humidity_flown** | Индикатор по влажности/дождю | Проверка осадков |

### SPOTS модель имеет 1 выход:

| Output | Описание |
|--------|----------|
| **flown** | Летальность для конкретного spot (takeoff) |

### Как оценить разные outputs

```bash
# Основная летальность
pyparaglide evaluate --year 2023 --model cells --output flown --threshold 0.1

# XC перспективы
pyparaglide evaluate --year 2023 --model cells --output crossed --threshold 0.05

# Индикатор по ветру
pyparaglide evaluate --year 2023 --model cells --output wind_flown --threshold 0.1

# Индикатор по влажности
pyparaglide evaluate --year 2023 --model cells --output humidity_flown --threshold 0.1
```

## Практические рекомендации

### Для CELLS модели

#### Рекомендуемые thresholds:

| Output | Threshold | F1 | Recall | Интерпретация |
|--------|-----------|----|----|----------------|
| **flown** | **0.1** | 0.42 | 99% | Поймать почти все лётные дни |
| **crossed** | **0.05** | 0.16 | 77% | XC условия редкие, нужен низкий threshold |
| **wind_flown** | 0.1 | (экспериментально) | - | Проверка ветра |
| **humidity_flown** | 0.1 | (экспериментально) | - | Проверка дождя |

#### Когда использовать flown vs crossed:

```
Flown: "Можно ли сегодня летать в принципе?"
→ Используйте для: решения ехать/не ехать на точку

Crossed: "Есть ли сегодня потенциал для XC?"
→ Используйте для: выбора места старта, планирования маршрута
```

### Для SPOTS модели

SPOTS модель показывает качество на уровне spot'а, а не региона. Рекомендации:

```bash
# Оценка SPOTS для конкретного spot
pyparaglide evaluate --year 2023 --model spots --threshold 0.2
```

**Важно:** SPOTS обычно имеет более низкий ROC AUC, чем CELLS, из-за меньшего количества данных.

## Примеры использования

### Пример 1: Найти оптимальный threshold

```bash
#!/bin/bash
# Скрипт для подбора threshold

for t in 0.05 0.1 0.15 0.2 0.25 0.3; do
    echo "=== Threshold: $t ==="
    pyparaglide evaluate --year 2023 --model cells --threshold $t --output flown
    echo ""
done
```

Смотрите на **F1 Score** для Flyable класса - выбирайте threshold где он максимален.

### Пример 2: Сравнить flown и crossed

```bash
# Flown (обычный полёт)
pyparaglide evaluate --year 2023 --model cells --output flown --threshold 0.1
# ROC AUC: 0.93, F1: 0.42, Recall: 99%

# Crossed (XC)
pyparaglide evaluate --year 2023 --model cells --output crossed --threshold 0.05
# ROC AUC: 0.92, F1: 0.16, Recall: 77%
```

### Пример 3: Оценить модель на разных годах

```bash
# Проверить обобщающую способность
pyparaglide evaluate --year 2021 --model cells --threshold 0.1
pyparaglide evaluate --year 2022 --model cells --threshold 0.1
pyparaglide evaluate --year 2023 --model cells --threshold 0.1
```

Если ROC AUC стабильный (~0.90+) по всем годам - модель хорошо обобщает!

## Интерпретация реальных результатов

### Пример: flown @ threshold=0.1

```
ROC AUC Score: 0.9263

Confusion Matrix:
  True Negatives:  5,553
  False Positives:    988
  False Negatives:      3
  True Positives:    356

Precision (Flyable): 26%
Recall (Flyable):    99%
F1 Score (Flyable):  0.42
```

### Разбор по пунктам:

1. **ROC AUC = 0.93**
   - ✅ Модель отлично различает классы
   - Модель может быть использована в продакшене

2. **Recall = 99%**
   - ✅ Из 359 лётных дней пойманы 356
   - ✅ Пропущено только 3 дня - отлично!

3. **Precision = 26%**
   - ⚠️ Из 1344 предсказанных "лётных" только 356 реально были лётными
   - ⚠️ 988 раз приехали зря

4. **F1 = 0.42**
   - ✅ Хороший баланс для несбалансированных классов
   - ✅ Лучший результат среди всех thresholds

5. **Практический смысл:**
   ```
   На каждые 100 поездок:
   - 26 дней реально полетаете ✅
   - 74 дня приехали зря ⚠️
   - Но: вы почти не пропускаете хорошие дни!
   ```

### Важное правило:

**Не смотрите только на Accuracy!**

```
threshold=0.4: Accuracy = 95%
- Но: TP = 0, FN = 359
- Модель вообще бесполезна - не предсказывает ни одного лётного дня!

threshold=0.1: Accuracy = 86%
- TP = 356, FN = 3
- Модель полезна, несмотря на более низкую accuracy!
```

## Часто задаваемые вопросы

### Q: Почему ROC AUC высокий, а F1 низкий?

**A:** ROC AUC измеряет **способность модели различать**, а F1 измеряет **качество при выбранном threshold**. Высокий ROC AUC говорит "модель может работать хорошо", но нужно подобрать правильный threshold.

### Q: Какой threshold выбрать для продакшена?

**A:** Для параплана рекомендуем **threshold=0.1 для flown**:
- Поймает 99% лётных дней
- Приемлемое соотношение FP/TP (~2.8)
- Лучший F1 Score

### Q: Почему crossed имеет более низкий F1?

**A:** XC дни встречаются в 3.5 раза реже обычных лётных дней (101 vs 359). Мало данных = хуже качество модели. Но ROC AUC всё ещё высокий (0.92), значит модель различает хорошо.

### Q: Можно ли использовать model=spots?

**A:** Да, но SPOTS обычно имеет более низкое качество (ROC AUC 0.5-0.7) из-за малого количества данных. Для продакшена рекомендуется CELLS.

### Q: Как часто нужно переобучать модель?

**A:** Запускайте `pyparaglide evaluate` на последних данных. Если ROC AUC упал ниже 0.85 - пора переобучить.

## Краткая шпаргалка

```bash
# Оценить flown
pyparaglide evaluate --year 2023 --model cells --output flown --threshold 0.1

# Оценить XC
pyparaglide evaluate --year 2023 --model cells --output crossed --threshold 0.05

# Подобрать threshold
for t in 0.05 0.1 0.15 0.2; do
    pyparaglide evaluate --year 2023 --model cells --threshold $t
done
```

### На что смотреть:

1. **ROC AUC** > 0.85 → модель хорошая
2. **Recall** (Flyable) > 70% → ловит большинство лётных дней
3. **F1** (Flyable) > 0.3 → приемлемый баланс
4. **FP/TP ratio** < 3 → не слишком много ложных тревог
